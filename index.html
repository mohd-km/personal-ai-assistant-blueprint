Digital Brain Architecture

A personal AI assistant whose memory is one folder of plain text notes that you own. I run the real one every day. If one hits its usage limit, the next carries on with the same notes.

PART 1: FOLLOW ONE REQUEST

One request, five stops

Front door → shared folder → cloud computer → your phone → your OK. Click any stop on the diagram to see what happens there.

The problemYou ask an assistant to do something, but you cannot see where your words go or what stops it from sending an email you did not mean to send.

How it worksEach request is a moving dot (a packet) that passes five stops. It comes in through one of four front doors: Telegram, the phone line, email or a private web app. The shared folder hands the right notes to a cloud computer that never switches off, an engine there does the work, and a short card comes back to your phone. The last stop is the approval gate, and it only stops money, publishing and anything that reaches another person.

Try this firstPress Send a client email. The dot stops at the last box and shows you the draft with Approve and Cancel. Pay a bill stops there too. Then try Remember travel preference: it passes straight through, because a private note needs no permission.

PART 2: CLOSE THE LAPTOP

Long jobs move to the cloud

A build that takes an hour should not keep your laptop open for an hour.

The problemAn assistant running on your laptop stops the moment the lid closes. Leave it open and the laptop is busy, hot and stuck at home.

How it worksWhen a job is long or heavy, the laptop hands it over: the conversation so far and any files you just changed go to the cloud computer, which starts the job as its own background process. From then on the laptop is free. When the job is done, one short card reaches your phone, with the detail behind a tap.

Try this firstPress Keep it on the laptop, then Close the laptop halfway: the job dies. Now press Hand it to the cloud and close the laptop again. It finishes anyway.

What keeps it running without anyone watching

A test after every script edit

The moment an AI changes one of the brain’s own programs, a syntax check and that program’s self-test run. A failure goes straight back to the AI that made the edit, before it does anything else.

Idle workers are cleared

At most two AI workers stay warmed up for quick replies. When memory runs low, idle ones are shut down first, so the server never chokes.

A warning before a limit bites

Each engine plan has a usage limit. You get one short warning when one is close, and work moves to the next engine instead of failing.

Jobs survive restarts

A handed-over job runs on its own, outside the chat that started it. If the server restarts a service, the job carries on, and a job can never start another job.

PART 4: WHEN AN ENGINE GOES DOWN

Switch an engine off

The backup plan is called failover: when one engine is unavailable or out of quota, the next one in line takes over.

The problemAI apps have outages and usage limits. An assistant tied to one of them stops when that one does.

How it worksThe three engines wait in a fixed order: Gemini, then Codex, then Claude. Work goes to the first one that is switched on and still has quota left. When one gets close to its usage limit you get one short warning, and once it hits the limit every channel skips it until it resets. All three read the same notes, so the backup already knows what the first one knew. Each runs on a fixed monthly plan, so a switch adds no pay-per-use charge.

Try this firstPress Use up its limit on Gemini. A warning appears, Codex moves to ACTIVE NOW, and the diagram in Part 1 shows Codex doing the work. Then switch Codex off too.

None of the three engines is available. Your notes stay safe in the folder, and nothing is charged, until one of them comes back.

Why this avoids surprise bills

Because every assistant reads the same folder of notes, moving from Gemini to Codex or Claude needs no copying and no repeating yourself. Many AI services also sell pay-per-use access (an API, where a program talks to the AI directly and is billed per word). This design only uses fixed monthly plans, so the extra pay-per-use cost stays at $0 even during an outage.

PART 5: WHAT IS IN THE MEMORY

Inside the 5 Folders

The whole memory is five ordinary folders of text files.

The problemChat apps keep what you told them inside long conversation histories. You cannot easily search them, fix them or take them with you.

How it worksEach folder holds one kind of knowledge: rules for how to behave, facts about you, past mistakes to avoid, step-by-step recipes and a log of everything done. The files are Markdown (plain text with a few symbols, such as # for a heading and - for a bullet point).

Try this firstClick Lessons Learned. You will see a sample note: one correction written here is followed by all three engines from then on.
